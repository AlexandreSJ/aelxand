Puddle

A lightweight REST API built with Go and the Gin framework, featuring automatic OpenAPI 3.1 documentation and a clean layered architecture.

Features

I followed this example, and went freestyle on some cool stuff i was learning. Feel free to check it out!

  • Gin Framework - Fast HTTP web framework with middleware support
  • Zero-annotation API Documentation - Automatic OpenAPI 3.1 spec generation with gin-docs
  • Layered Architecture - Clean separation of concerns (handlers → store → data)
  • Dependency Injection - Handler dependencies injected at startup
  • Interactive API Docs - Swagger UI and Scalar UI out of the box
  • Hot Reload - Development with Air for rapid iteration
  • TUI Components - Terminal User Interface using the Charm ecosystem (planned)

Architecture

Puddle follows a layered architecture pattern:

HTTP Request → handler → store → Data
                 ↓
           JSON Response
  • Handlers - Parse requests, delegate to store, format responses (no business logic)
  • Store - Data access layer handling CRUD operations (currently in-memory, swappable)
  • Models - Data structures shared across layers

Dependency injection is used to wire components in main.go:

albumStore := store.NewAlbumStore()
albumHandler := handler.NewAlbumHandler(albumStore)
r := router.SetupRouter(albumHandler)

Getting Started

If you want to install this project and try for yourself, jsut keep reading this section.

Prerequisites

  • Go 1.26.2 or later
  • (Optional) Air for hot reload

Installation

# Clone the repository
git clone https://github.com/yourusername/puddle.git
cd puddle

# Build the project
make build

Run

# Run the server
./build/puddle

# Or with hot reload during development
make run

The server starts on http://localhost:8081.

API Endpoints

Method Path Description
GET /api/v1/ping Health check
GET /api/v1/albums List all albums
GET /api/v1/albums/:id Get album by ID
POST /api/v1/albums Create a new album
DELETE /api/v1/albums/:id Delete an album

API Documentation

Interactive API documentation is available at:

  • Swagger UI: http://localhost:8081/docs
  • Scalar UI: http://localhost:8081/docs?ui=scalar
  • OpenAPI Spec: http://localhost:8081/docs/openapi.json

Development

Running with hot reload

make run

This uses Air to automatically rebuild on file changes.

Clean build artifacts

make clean

Tidy dependencies

make tidy

Example

Create a new album:

curl -X POST http://localhost:8081/api/v1/albums \
  -H "Content-Type: application/json" \
  -d '{"id": "1", "title": "Blue Train", "artist": "John Coltrane", "price": 56.99}'

List all albums:

curl http://localhost:8081/api/v1/albums

Documentation

What i think is pretty cool is that you can easily open OpenAPI Swagger, which is usually automatically created, and then switch with ScalarUI.

Just call /docs and change the view by clicking on the top-right button, or open:

http://localhost:8081/docs?ui=swagger

#or

http://localhost:8081/docs?ui=scalar
